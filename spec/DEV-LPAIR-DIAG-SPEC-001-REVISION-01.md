- the outcome vocabulary (SUPPORTED / NOT_SUPPORTED / INCONCLUSIVE / UNKNOWN) and the rule that failure to support a cause is not proof that the cause is absent.

Where this revision **replaces** a section, the replacement text is given in full in §2–§5 below, and the original section must no longer be used for that point. Where this revision **adds** a definition that the original implied but did not give (approach-cell geometry, clock convention, suitable-action reference, aggregation rule), the addition is marked as such, and any original cross-reference that implied the definition already existed is corrected in §1.

**What this revision changes, in one paragraph:**
The original specification conflated three things that must be kept apart: (1) a **coverage observation** (a door cell was or was not visited) with a **causal discovery diagnosis** (insufficient exploration explains the failure); (2) a **step-level observation** (this action was not in the optimal set at this step) with a **job-level causal diagnosis** (decision failure explains this job); and (3) a **model-dependent judgement** (a head's argmax) with an **independent reference** (what the environment itself makes optimal). It also left the clock convention, the approach-cell geometry, and the Dec1 data requirement underspecified. This revision separates all three, defines an independent time-expanded optimal-action reference, fixes the clock/transition convention from the actual world code, makes full head Q-values mandatory if Dec1 is to be assessed at all, and narrows the first collection's scope to what it can actually assess. It does **not** change the verdict on existing evidence — that verdict remains INCONCLUSIVE for the four categories (UNKNOWN for the missing job) — because the corrections concern how a *future* diagnostic would classify, not what the existing records already prove.

**Evidence labels, as in the original:** OBSERVED, INFERENCE, HYPOTHESIS, PROPOSAL, UNKNOWN. New definitions in this revision are PROPOSAL until the owner approves them. Code-derived facts about the world are OBSERVED from the code read for this revision (see §6, provenance note).

## 2. Revised §3.1 — Coverage, discovery, and earlier policy failure (supersedes original §3.1 in full)

### 2.1 Three claims that must never be merged

**Claim 1 — Coverage observation (OBSERVED fact, once trajectories exist; INCONCLUSIVE on existing records).**
Whether the relevant door cell, entry cell, wall-adjacent cells, and usable crossing states were visited, in which episodes, and at which ticks/phases. Coverage is a fact about a trajectory, not a cause. It is defined in §2.2 (geometry) and §2.3 (usable states). Its exact rule is retained: a count of zero for a defined set is an exact coverage fact (count = 0), not a threshold.

**Claim 2 — Causal discovery diagnosis (HYPOTHESIS until a separate criterion is met).**
Whether *insufficient discovery or exploration* explains the failure. This claim requires more than coverage, because an earlier policy failure can produce the same coverage. In particular:
- In **greedy evaluation** (ε = 0, the pilot's eval protocol), there is **no exploration mechanism** to fail. A greedy agent that never visits the held-out door row has not "failed to explore" in any mechanism sense; it has followed its (frozen) policy, and that policy did not lead it to the door. Calling that a "discovery failure" as a *cause* adds no mechanism beyond "the policy did not go there", which is already the knowledge/decision question. **Therefore: D2-causal, as a separate causal category in greedy eval, is INCONCLUSIVE under this revision unless the owner specifies a distinct exploration mechanism whose failure is being claimed** (for example, a stated exploration policy that was supposed to operate during eval — none operated in the pilot — or a stated training-to-eval transfer mechanism). Without such a specification, the correct statement for a never-visited door in greedy eval is: **"Coverage: door cell never visited (count = 0). Causal discovery diagnosis: INCONCLUSIVE — earlier knowledge/decision failure is not excluded."**
- In **training** (ε-greedy, 1000 episodes), D1-causal is a distinct claim in principle, because an exploration mechanism *did* operate. Even there, coverage alone does not establish it: a training agent could fail to visit the trained door approach because exploration was insufficient, *or* because its learned values (even under exploration) repeatedly led it away, *or* because the approach is hard to reach by random exploration within 1000 episodes. D1-causal therefore requires, at minimum: (a) training trajectories with per-step position (not available in the pilot), (b) a pre-defined expected-visitation reference (for example, visitation under a stated random-exploration baseline, or visitation in a stated number of episodes — **owner decision, not defined in this revision**, because no such baseline was preregistered for the pilot), and (c) a demonstration that the policy's values on start states did not themselves explain the non-visitation. **Therefore: D1-causal is NOT ASSESSABLE with the first (held-out eval only) collection, and is INCONCLUSIVE on existing evidence and on that collection's scope (see §6).**

**Claim 3 — Earlier policy failure (knowledge or decision, §3.5).**
Whether knowledge or decision errors prevented the agent from reaching the coverage states. This claim is assessed *on the steps that were actually visited*, using the reference in §3 and the Q patterns in §3.5. It is the claim that must be excluded before any causal discovery claim can be made, and the original §3.1C got the direction wrong: it required excluding *downstream* failures, when the confound for discovery is *upstream* (earlier) policy failure. The corrected exclusion is: **a causal discovery claim requires showing that, on the steps leading to the coverage gap, the policy's values and choices were *not* the reason for the gap** — for example, that the agent's values on start states ranked approach actions highest and the selector chose them, yet the agent still did not reach the door because of a stated exploration/transition limitation. No such showing is possible from the pilot's aggregates, and no such showing is possible from held-out eval trajectories alone without a stated exploration mechanism (see above).

### 2.2 Approach-cell geometry — defined precisely (supersedes the implied definition in original M-D3)

For the pilot's single-door worlds, let `wx` be the wall column, `dy` the door row, `N` the grid size. The worlds in scope are:
- W10 trained: `wx = 5, dy = 5, N = 10`; W10 held-out (W10h): `wx = 5, dy = 2, N = 10`.
- W20 trained: `wx = 10, dy = 10, N = 20`; W20 held-out (W20h): `wx = 10, dy = 5, N = 20`.

Definitions (all positions are (x, y) grid cells; movement is up/down/left/right only, no diagonals):
- **Door cell D** = {(wx, dy)} — the single cell in the wall column through which crossing is possible.
- **Entry cell E** = {(wx − 1, dy)} — the *only* occupiable cell from which a single move right enters D. The other neighbours of D are (wx + 1, dy) (goal side, not a start-side approach), (wx, dy − 1) and (wx, dy + 1) (wall-column cells, blocked, not occupiable except D itself). E is therefore a singleton, not a corridor, for entry purposes.
- **Wall-adjacent set W** = {(wx − 1, y) : 0 ≤ y < N} — all start-side cells immediately west of the wall column. Visiting W but never E means the agent reached the wall at the wrong row.
- **Start-side set** = {cells with x < wx}. **Goal-side set** = {cells with x > wx}. A held-out job that never visits the goal-side set has never crossed, regardless of whether it visited D or E.
- **Coverage levels, in order (each level's fact does not imply the next):**
  - **L0 — Never reached the wall:** W never visited (count = 0 over the job).
  - **L1 — Reached the wall, wrong row:** W visited, E never visited.
  - **L2 — Reached the entry cell:** E visited at least once.
  - **L3 — Occupied the door cell:** D visited (as position_before at some step, or as position_after of a step — see §4 for the tick at which occupancy is counted).
  - **L4 — Crossed to the goal side:** goal-side set visited at least once.
  Each level is a coverage fact with its own count and denominator (steps in the job/episode). No level, by itself, is a causal diagnosis.
- **Trained-world counterparts** use the same definitions with the trained dy (5 for W10, 10 for W20). A held-out coverage claim must state which dy it uses; a trained-vs-held-out coverage comparison must not mix dy values.

If the owner prefers a wider approach definition (for example, a corridor of cells within Manhattan distance ≤ 2 of D on the start side), that definition must be stated as an owner decision **before** collection, and the L0–L4 levels above must be re-derived from it. Until then, the singleton-E definition above governs, because it is the only definition that follows from the world's movement rules (single-step entry into D).

### 2.3 Usable crossing states — defined from the transition rules, not from narrative

A state is a pair **s = (position_before, phase)**, where phase = t_pre mod 20 (see §4). Door open at s iff phase ∈ {0, …, 9} (period 20, open_len 10, OBSERVED from `world_exp1.py`).
- **Usable entry state:** position_before = E, phase ∈ {0, …, 8}, and the reference action at s is RIGHT (enter D). Rationale, from the transition rules: entering D at tick t_pre requires open at t_pre (phase ≤ 9); leaving D at the next step requires open at t_pre + 1 (phase + 1 ≤ 9, i.e. phase ≤ 8). Entering at phase 9 (last open tick) is **fatal by construction**: at the next step the agent is in D at a closed tick and is crushed before movement (see §4.1, step 2). A "move closer to the door" rule that counts entering at phase 9 as suitable is therefore **incorrect** and must not be used.
- **Usable exit state:** position_before = D, phase ∈ {0, …, 9}, and the reference action at s is RIGHT (leave D to the goal side). Leaving D at an open tick is safe regardless of the next tick's phase, because the agent is no longer in D at the next step's crush check.
- **Crush-forced state:** position_before = D, phase ∈ {10, …, 19} (closed). At such a state the world crushes the agent before movement, regardless of the action (see §4.1). No action at such a state is diagnostic for knowledge/decision (see §3.5, step-pattern priority).
- **Non-usable approach state:** position_before = E, phase ∈ {9} (entry would be fatal next step) or phase ∈ {10, …, 19} (door closed, entry blocked). At such a state the suitable reference action is **not** RIGHT; it is whatever the optimal set R(s) contains (typically WAIT/STAY or a move that keeps the agent at E or moves it within the start side without entering D — see §3.2, where R(s) is computed, not narrated).

These definitions are **PROPOSAL** in the sense that they are derived from the coded transition rules, not from model data. Their derivation is checkable against `world_exp1.py:step` (§4.1), and any disagreement between the derivation and the code must be resolved in favour of the code, with the definition corrected, before collection.

### 2.4 Revised decision rules for coverage and discovery

- **Coverage fact (per job, per episode, per level L0–L4):** Report the count and denominator exactly (for example, "D visited in 0/4000 steps, 0/20 episodes" or "E visited in 12/4000 steps, 3/20 episodes"). No causal label is attached to a coverage fact.
- **D2-causal (greedy eval):** **INCONCLUSIVE** under this revision, unless the owner specifies a distinct eval exploration mechanism and a pre-defined criterion for its failure (owner decision, §7). A future trajectory showing L0, L1, or L2 coverage does **not** change this to SUPPORTED by itself.
- **D1-causal (training):** **NOT ASSESSABLE** with the first collection (held-out eval only). **INCONCLUSIVE** on existing evidence. Requires training trajectories + a pre-defined expected-visitation reference (owner decision, §7).
- **NOT_SUPPORTED for D2-coverage (i.e. the coverage claim itself is false):** If trajectories show D visited (L3) or goal-side visited (L4), then the coverage claim "door never visited" is false for that job. That does **not** by itself establish any downstream cause; it only moves the diagnostic to §§3.5–3.6 (knowledge/decision/execution on the visited states).
- **UNKNOWN:** The job does not exist (L-SVA W20 seed 2), or the geometry (dy, wx) for the job's eval_world is not stated, or the trajectory's clock convention (§4) is not followed, so that "visited at phase p" cannot be trusted.

## 3. Revised suitable-action reference — time-expanded optimal-action set (supersedes original T27 and the example in original §3.2D)

### 3.1 Why a computed reference, not a narrative rule

The reference must be independent of the model in three senses: (1) it must not use the model's Q-values, chosen actions, or failed trajectory as evidence for what was suitable; (2) it must use only the environment's specified geometry, transition rules, and true schedule; (3) it must be computable for every state the agent could be in, including states the agent never visited, so that "suitable" is defined even where the agent did not go. A narrative rule ("move closer") fails (1) and (3) in the waiting/crossing/blocked cases, and it fails to handle multiple optima. The construction below satisfies all three, because it is a shortest-path computation on the environment's own state graph.

### 3.2 Construction (PROPOSAL, checkable against the world code)

**State space (for one world, one door, period 20, open_len 10):**
- A state is **s = (position, phase)**, where position = (x, y) with 0 ≤ x, y < N, and phase = t mod 20 for the world tick t at which the state is occupied (position_before at that tick).
- The goal state is position = (N − 1, N − 1), any phase. Episodes end on reaching the goal; no action is defined at a goal state (episode terminated).

**Transition function T(s, a) — exactly mirroring `Exp1World.step` at tick t with phase p = t mod 20, open = (p < 10):**
- Let position_before = pos, action a ∈ {up, down, left, right, stay}, delta(a) as in `world.py:ACTIONS`.
- **Crush-forced case:** if pos ∈ door_cells and not open, then T(s, a) = (start (0, 0), phase (p + 1) mod 20) for **every** a, with crush = True, and no movement occurs. The action is ignored by the world.
- **Otherwise:** target = clip(pos + delta(a), grid bounds) (clipping as in the code: x and y each clamped to [0, N − 1]); blocked = (target is a wall/obstacle cell) **or** (target ∈ door_cells and not open); if blocked and target ≠ pos, then T(s, a) = (pos, phase (p + 1) mod 20) with blocked = True; else T(s, a) = (target, phase (p + 1) mod 20). If the resulting position is the goal, the episode terminates at that step.
- **Stay and edge-clip equivalence (OBSERVED from the code):** stay has delta (0, 0), target = pos, and the world logs "move", not "blocked". An edge move whose clipped target = pos likewise logs "move", not "blocked". Both therefore have the same transition as stay, and both are in the optimal set exactly when stay is. They must not be counted as blocked (see C06).

**Value function V(s) — minimal steps to goal:**
- V(goal, any phase) = 0.
- For non-goal s, V(s) = 1 + min_a V(T(s, a)), where V(T(s, a)) = 0 if T(s, a) is the goal (episode terminates), and the minimum is over all 5 actions. This is the standard shortest-path value on the finite directed graph with N² × 20 nodes and 5 edges per node, all costs 1. It is computed by exact shortest-path (Dijkstra / BFS on the time-expanded graph, or value iteration to convergence — the method is an implementation choice for the reference computation, not a diagnostic claim, provided the resulting V satisfies the Bellman equation above to exact integer equality).
- **Finiteness for the pilot worlds (INFERENCE, to be verified by the reference computation before use):** for W10/W20 and their held-out variants (no interior obstacles), V(s) is finite for every s, because from any start-side position the agent can wait for an open window, enter D at a usable phase, exit to the goal side, and walk to the goal, and from any goal-side position it can walk to the goal directly. The maximum V over start states is well below the 200-tick cap (Manhattan distance ≤ 38 for W20, plus at most one waiting period for a usable window). If the reference computation finds V(s) = ∞ for some s in a future world (for example, with obstacles), then R(s) is empty for that s, the step is marked **UNREACHABLE** (not a decision error), and no Dec/K claim may be made from that step.
- **Cap-aware recoverability:** for a step s in an episode with local step index s_idx (0-based, see §4), steps remaining after the step = 200 − (s_idx + 1). A next state s' is **recoverable** iff V(s') ≤ steps remaining after the step. A step is **cap-fatal** iff V(T(s, a_taken)) > steps remaining after the step (i.e. even optimal play from the next state cannot reach the goal before the cap). Cap-fatal is an exact, threshold-free concept (it uses only V and the cap, both specified).

**Optimal-action set R(s) — the reference:**
- If s is a goal state: R(s) is undefined (episode ended; no step to judge).
- If s is crush-forced (pos ∈ door_cells, phase closed): **R(s) = all 5 actions**, with diagnostic flag **NON-DIAGNOSTIC**. Rationale: the world ignores the action at such a step, so membership in R(s) carries no information about knowledge or decision. Such steps are **excluded** from Dec/K denominators (see §4.4) and must not be counted as optimal or suboptimal.
- Otherwise: **R(s) = { a | V(T(s, a)) + 1 = V(s) }**, where V(T(s, a)) = 0 if T(s, a) is the goal. R(s) is a **set**, not a single action. Multiple actions can be in R(s) (for example, stay and a blocked move that both leave the position unchanged, or two different moves that both lie on *some* shortest path). An action is **OPTIMAL** iff it is in R(s); **SUBOPTIMAL** iff it is not in R(s) (and s is not crush-forced and not goal).
- **How R(s) handles the cases the narrative rule could not:**
  - *Waiting:* at a start-side or entry state during a closed period, or at an entry state at phase 9, the optimal action(s) will typically include STAY (and any outcome-equivalent blocked move), because moving into D at a closed or last-open tick is blocked or fatal and therefore increases V. Stay is therefore suitable exactly when R(s) contains it, not by a separate "waiting is good" narrative.
  - *Timing / crossing:* R(s) contains RIGHT at E exactly when entering D at that phase is on a shortest path, which (by the transition rules) requires phase ∈ {0, …, 8} for entry (so that exit at the next step is still open) — see §2.3. Entering at phase 9 is not in R(s) (it leads to crush, then to start, increasing V), even though it "moves closer" to the goal in Euclidean terms.
  - *Blocked moves:* a blocked move and stay have the same transition (position unchanged, phase + 1), so either both are in R(s) or neither is, depending on whether staying at that position for one tick is on a shortest path. A blocked move is therefore not automatically an error, and a stay is not automatically correct — both are judged by R(s).
  - *Progress:* moving away from the door/goal increases V (it requires extra steps to return), so it is not in R(s) unless no other action is optimal (for example, in a state where all moves are blocked except a detour — but in the pilot's obstacle-free worlds, a detour is never required for a shortest path, so moving away is suboptimal in those worlds; in a future world with obstacles, R(s) must be recomputed for that world's geometry, not reused from W10/W20).
  - *Multiple optima:* if two actions are both in R(s), either is suitable, and the diagnostic must not penalise choosing one over the other. The step-level judgement is set membership, not argmax identity.

### 3.3 What the reference is, and is not

- **It is** a post-hoc, model-independent, environment-grounded optimal set, computed offline from geometry + transition + schedule, for every (position, phase) state.
- **It is not** a claim that the model *should* have been optimal, or that suboptimality is by itself a diagnosis. Suboptimality is a step-level observation; its causal attribution (knowledge vs decision vs schedule) requires the Q patterns in §3.5 and the aggregation rule in §4.4.
- **It is not** a substitute for the model's own values. A step where the taken action is in R(s) is *suitable by the reference*, regardless of what the model's Q said. A step where the taken action is not in R(s) is *unsuitable by the reference*, regardless of what the model's Q said. Whether that unsuitability is due to values, selector, or schedule knowledge is a separate question (§3.4–§3.5).
- **If the reference cannot be computed** (for example, because a future world's geometry or transition rules are not specified, or because V is infinite for the relevant states and no alternative "acceptable" definition is agreed), then **decision-versus-knowledge separation remains INCONCLUSIVE** for those states, per the work order. The reference must not be replaced by a head's argmax, by the taken action, or by the failed trajectory's own actions.

### 3.4 Schedule knowledge (K3) — separated from value/selector error by a mismatch test

For each step s (non-crush-forced, non-goal), let:
- **True schedule features at t_pre:** true_phase = t_pre mod 20; true_remaining = (10 − true_phase) if true_phase < 10 else 0; true_open = (true_phase < 10).
- **Recorded schedule features at the step's encode (t_pre):** K_rec (0/1), phase_rec = (recorded phase value) × 20, remaining_rec = (recorded remaining value) × 10, where the recorded values are the encoder vector slots [n+1] and [n+2] (scaled by 20.0 and 10.0 in `lpair.py`), rounded to the nearest integer for comparison (the underlying values are integer ticks scaled by exact factors, so rounding is exact, not a tolerance).
- **K-mismatch at step s:** K_rec = 1 **and** (phase_rec ≠ true_phase **or** remaining_rec ≠ true_remaining). This is an exact comparison (no tolerance, no threshold), because the schedule is deterministic and periodic.
- **K-unknown at step s:** K_rec = 0. This is **not** automatically a mismatch: at the first episode's first steps, estimates do not yet exist (protocol, see C12), and after a contradiction the model honestly returns None rather than a wrong estimate. K-unknown must be reported as such, with the episode index and step index, so that first-episode blank-start steps are not counted as K3 failures.
- **Timing-critical steps** for K3: steps where position_before ∈ {E, D} **or** the taken action is a move into D or out of D. On non-timing-critical steps, a K-mismatch is recorded as "K-mismatch present" but is **not** by itself a K3-causal step, because the step's outcome does not depend on timing in the same direct way.
- **Step-level K3 rule (PROPOSAL, to be approved with the reference):**
  - If the step is timing-critical **and** K-mismatch holds **and** the taken action is SUBOPTIMAL by R(s), then the step is classified **K3-CANDIDATE (preceding)** — schedule knowledge is a preceding candidate, and value/selector attribution for that step is **suspended** (the step is not counted as K2 or Dec, because the model's input at that step was wrong in a way that could explain the Q error). This is a precedence rule for attribution, not a proof that K3 caused the step's failure; a job-level K3 claim still requires aggregation (§4.4) and the threshold in §7.
  - If the step is timing-critical **and** K_rec = 1 **and** phase_rec/remaining_rec match the true schedule **and** the taken action is SUBOPTIMAL, then K3 is **NOT_SUPPORTED for that step** (schedule knowledge was correct at that step, so it cannot explain that step's suboptimality).
  - If K_rec = 0 on a timing-critical step, the step is classified **K-UNKNOWN** (not K3, not K2/Dec), unless the step is in the first episode's pre-estimate phase, in which case it is classified **K-BLANK-START** (protocol, not a failure) and excluded from K3 denominators. The distinction between K-UNKNOWN and K-BLANK-START requires knowing, for the job, the first tick at which estimates became available (ScheduleModel `first_estimates_tick` — a field that must be recorded at job level in any future collection, see §5, field R-EST).

### 3.5 Knowledge vs decision — step-pattern table (supersedes original §§3.2C and 3.3C, and Dec2 reclassification in C04)

For each **non-crush-forced, non-goal, timing-critical or relevant step** s, let:
- **suitable_act_set** = {act : the action taken by that act's head at s (its argmax action) is in R(s) as an *action*}. Note: R(s) is a set of *actions* (up/down/left/right/stay), while acts are selector choices (ACT-0/1/2). An act is "suitable" at s iff its head's greedy action at s is in R(s). This requires full head Q (all three heads' argmax actions) — see C08. If full head Q is not recorded, suitable_act_set cannot be computed, and Dec1/Dec3 patterns below cannot be assigned.
- **taken_act** = selector argmax at s (the act actually chosen in greedy eval).
- **taken_action** = the taken act's head argmax action at s (the action actually executed, subject to the transition rules in §4).
- **selector_Q** = selector network's 3 Q-values at s; **head_Q[act]** = that act's head 5 Q-values at s.

**Step patterns (SVA — separate networks, separation possible in principle):**

| Pattern at step s | Conditions (all must hold) | Step classification |
| --- | --- | --- |
| P-OPT | taken_action ∈ R(s) | OPTIMAL step. Not a Dec/K error at this step, regardless of Q. (Execution may still fail at this step if the transition is blocked/crush — but for a non-crush-forced step, a taken action in R(s) that is blocked is outcome-equivalent to stay, and R(s) already accounts for blocked equivalence; see §3.2.) |
| P-SEL | taken_act ∉ suitable_act_set, AND suitable_act_set is non-empty (at least one act's head action ∈ R(s)), AND K-mismatch does **not** hold at s (or s is not timing-critical for K3 — see §3.4 precedence) | **Dec1 (selector-ranking) step error.** The selector chose an act whose head action is unsuitable, while a suitable act existed. This is a selector-value ranking error, not a head-value error for the suitable act. |
| P-HEAD | taken_act ∈ suitable_act_set is false because the taken act's head action ∉ R(s), AND suitable_act_set is empty (no act's head action ∈ R(s)), AND K-mismatch does not hold at s | **K2 (head-value) step error.** No head would have chosen a suitable action at s, so no selector choice could have succeeded at s. This is a head-value error, not a selector error. (Original Dec2 is this pattern, reclassified as K2 per C04.) |
| P-BOTH | taken_act ∉ suitable_act_set, AND suitable_act_set is empty, AND the selector also did not choose a suitable act (trivially, since none exists) — i.e. both selector ranking and head values are wrong at s, in the sense that the selector's chosen act is unsuitable *and* no act is suitable | **BOTH / AMBIGUOUS step.** Cannot be assigned solely to Dec1 or solely to K2. Counted separately in aggregation; must not be counted as Dec1 alone or K2 alone. |
| P-K3 | Timing-critical step, K-mismatch holds, taken_action ∉ R(s) | **K3-CANDIDATE step** (preceding, see §3.4). Not counted as Dec1/K2 for that step. |
| P-KUNK | K_rec = 0 on a timing-critical step (and not K-BLANK-START) | **K-UNKNOWN step.** Excluded from Dec/K denominators for that step; counted in a separate K-unknown denominator. |
| P-CRUSH | s is crush-forced (position_before ∈ D, phase closed) | **NON-DIAGNOSTIC step.** Excluded from Dec/K denominators. Causal attribution, if any, belongs to the earlier entry/stay step that placed the agent in D (see §4.5), not to this step. |

**Step patterns (L-SHARED — single network, separation NOT possible at mechanism level):**
- The same P-OPT / P-SEL-like / P-HEAD-like / P-BOTH patterns can be *computed* (selector Q = first 3 outputs, head Q = last 15 outputs reshaped to 3×5), but they must **not** be interpreted as separate mechanism attributions, because selector and heads share a hidden representation. A pattern that looks like P-SEL in Shared could be caused by the shared representation error, not by a separate selector mechanism.
- **Therefore, for Shared: step patterns are reported descriptively (pattern counts), but mechanism-level Dec vs K classification is INCONCLUSIVE even with trajectory + full Q.** The only mechanism-level statements available for Shared are: (a) step was OPTIMAL or SUBOPTIMAL by R(s) (model-independent, valid for both constructions); (b) step was K3-candidate / K-unknown / crush-forced by the tests above (valid, because K3 is about input features, not about network separation); (c) step was head-value error in the sense that no head's action was suitable (P-HEAD pattern, descriptive) — but this must be labelled "head-value pattern (Shared, mechanism ambiguous)", not "K2 as a separate mechanism".
- Any future Shared claim that separates Dec from K by Q alone, without an additional intervention (for example, a counterfactual evaluation in which the selector is forced to a suitable act and the head's action is observed — which would be a new experiment, not a diagnostic observation, and is not authorised by this revision), is **invalid** under this revision.

**Dec3 (SVA coordination) — revised status:**
- Dec3 as a *descriptive* pattern is: selector argmax ≠ argmax over heads of (max action value per head) at s. This pattern can be computed from Q (it is the existing `selector_vs_headvalue` agreement, per step instead of aggregated). It is **not** a causal diagnosis by itself, because head-value argmax is not ground truth (confounding C-5: heads trained on different state distributions, values not calibrated across heads).
- Dec3 becomes a causal pattern **only** when it coincides with P-SEL (suitable act exists, selector did not choose it). In that case it is reported as Dec1, with Dec3 noted as a descriptive correlate, not as a separate cause. Dec3 without P-SEL (selector ≠ head-value best, but taken action ∈ R(s), or no suitable act exists) is **not** a decision error.

## 4. Revised clock, transition, aggregation, and earliest-failure rules (supersedes original §3.4B–E, §3.5, and parts of §3.6–§3.7)

### 4.1 Clock convention — from the code, stated unambiguously (OBSERVED)

Code sources: `Exp1World.reset/step` in `TEMPLATE/world_exp1.py`, `LEncoder.encode/reset` in `dev-lpair-001/lpair.py`, `eval_job` loop in `dev-lpair-001/lpair.py`, `ScheduleModel.observe` in `TEMPLATE/nn/wrapper.py`. The convention below is derived from those sources; if any future code change alters the convention, the convention must be re-derived and the schema versioned (see §5, field R-CFG).

- **Episode start:** `w.reset(start_tick = S)`, where S ∈ {0, …, 19} is the job's start_phase for that episode (pilot eval loops S = 0..19 in order). After reset: world tick = S, agent = (0, 0), log = [], `_door_prev = None`, `_was_on_goal = False`.
- **Encoder reset (no recorded step):** `enc.reset(w)` observes at tick S (door_open(S), position (0, 0)), sets prev_door to door_open(S), and calls `ScheduleModel.new_episode()` (clears pending previous observation, marks span gapped; events/estimates persist from previous episodes in the job). **No state row is recorded for the reset observation.** The first recorded step row is the first encode after reset (see below).
- **Local step index:** s = 0, 1, 2, … within an episode, in order. s is the episode-local step index, distinct from the world tick and from the start_phase.
- **World tick before action (governing tick):** **t_pre(s) = S + s**. This is the tick at which the encode happens, at which ScheduleModel.observe is called, and at which `world.step` evaluates the transition. It is **not** S + s + 1, and it is **not** s alone.
- **World tick after action:** **t_post(s) = S + s + 1 = t_pre(s) + 1**. This is the tick at the next step's encode (if the episode continues), and the tick at which the door schedule for the *next* step is evaluated. It must never be used as the governing tick for step s.
- **Phase:** phase(s) = t_pre(s) mod 20. Door open at step s iff phase(s) < 10. This is the true schedule; it is independent of the model's estimates.
- **Encode at step s (before action):** `x_s = enc.encode(w)` at tick t_pre(s). `encode` calls `world.observe()` (position_before, door_open_pre = door_is_open(t_pre)), then `ScheduleModel.observe(t_pre, door_open_pre)` (return value = contradiction flag for that encode), then computes K/phase/remaining from the model's state *after* processing the observation at t_pre (and after all previous observations in the job, with the episode-start gap). **K/phase/remaining in x_s are therefore features at t_pre, not at t_post, and not features of the next state.**
- **Action at step s:** a_s = `agent.act_greedy(x_s)` (selector argmax, then that head's argmax action). a_s is a function of x_s (and therefore of t_pre), not of t_post.
- **Transition at step s (world.step, in code order):**
  1. **Door log:** open_now = door_is_open(t_pre). If open_now ≠ `_door_prev` (initially None after reset, so the first step always logs the initial door state), log (t_pre, "door", "open"/"closed") and set `_door_prev = open_now`. This log is a *record*, not a decision input.
  2. **Crush check (pre-movement):** if position_before ∈ door_cells **and** not open_now, log (t_pre, "agent", "crushed"), set agent = (0, 0), clear goal tracking, set tick = t_post, and **return immediately** — no movement, no blocked/move log, no goal log for this step. **Crush at step s is therefore a function of position_before and t_pre, not of a_s.** The action a_s at a crush step is ignored by the world (see §3.2, crush-forced case).
  3. **Move (if not crushed):** target = clip(position_before + delta(a_s), grid bounds); blocked = is_blocked_cell(target) **or** (target ∈ door_cells and not open_now); if blocked **and** target ≠ position_before, log (t_pre, "agent", "blocked at (x, y)") and position_after = position_before; else position_after = target and log (t_pre, "agent", "move to (x, y)"). Note: stay (delta (0, 0)) has target = position_before, so it logs "move", not "blocked". An edge move whose clipped target = position_before likewise logs "move", not "blocked".
  4. **Goal log:** if position_after = goal and the agent was not already on the goal, log (t_pre, "goal", "reached") and set goal tracking. Episode ends in `eval_job` after this step (break), with ticks counted including this step.
  5. **Clock increment:** tick = t_post (t_pre + 1), whether the step was a crush, a blocked move, a move, a stay, or a goal step. Every step consumes exactly one tick.
- **Next step:** if the episode has not ended (reached) and s + 1 < 200, the next step s + 1 encodes at t_pre(s + 1) = t_post(s) = S + s + 1, with position_before = position_after of step s (or (0, 0) if step s was a crush, because the agent was reset to start *during* step s, before the next encode).

### 4.2 What "door_open" means in the revised schema (and what it must not mean)

- **door_open_pre (governing, mandatory):** door_is_open(t_pre(s)). This is the door state that governed the crush check and the blocked/entry decision at step s, and the door state the model observed at encode (via `world.observe()` at t_pre). All timing judgements (usable entry/exit, K-mismatch, Ex3) must use door_open_pre.
- **door_open_post (optional, labelled, never governing):** door_is_open(t_post(s)). This may be recorded for completeness (for example, to show that the door closed immediately after entry), but it must be labelled "post-transition schedule at t_post, not the decision input for step s" in every record and every analysis. **Any analysis that uses door_open_post as if it governed step s, or that aligns Q at step s with door_open_post, is INVALID for that step and returns INCONCLUSIVE for that step's timing classification.**
- **A one-tick ambiguity must not be interpreted as evidence for a policy or execution failure.** If a future trajectory's tick alignment cannot be verified (for example, if t_pre cannot be reconstructed from S + s, or if door_open_pre does not equal door_is_open(t_pre) for the recorded tick), then the affected steps' timing classifications are UNKNOWN, not "policy error" or "execution error". The validation gate in §5 (field R-VAL) must check tick alignment before any timing claim is accepted.

### 4.3 Blocked, stay, edge-clip, crush, and goal — transition types (replaces original T22 loose definition)

For each step s, record **transition_type** as exactly one of:
- **crush:** world logged "crushed" at t_pre (position_before ∈ door_cells, door closed at t_pre). position_after = (0, 0) (start), by the world's reset, not by movement. Action a_s is ignored.
- **blocked:** world logged "blocked at" at t_pre (target is wall/obstacle/closed-door and target ≠ position_before). position_after = position_before, by blocking, not by stay.
- **stay:** a_s is the stay action (delta (0, 0)). position_after = position_before, by choice, not by blocking. World logs "move", not "blocked".
- **move:** otherwise (including edge-clipped moves, where target after clipping = position_before but the world logs "move", not "blocked"). position_after = target (which may equal position_before only in the edge-clip case, and that case must be flagged by a separate **clipped** boolean: True iff the unclipped target would have been outside the grid bounds — if the collection code cannot recover the unclipped target from the world code, record clipped = UNKNOWN for that step, not False).
- **goal:** a subtype of move (or, in principle, of stay if the agent starts on the goal — impossible in the pilot, since start is (0, 0) and goal is (N − 1, N − 1)): position_after = goal, and the episode ends after this step. Record goal as a separate boolean (reached = True) in addition to transition_type, so that goal steps are identifiable without parsing transition_type.

**Blocked must not be inferred from position_after = position_before alone.** That inference conflates blocked, stay, and edge-clip, which have different diagnostic meanings (blocked = environment prevented movement; stay = policy chose not to move; edge-clip = policy chose a move that the grid bounds prevented). The schema must record the world's own blocked log event, or the blocked classification for that step is UNKNOWN.

### 4.4 Aggregation — from step observations to job-level claims (supersedes original §3.3C/D and §3.4C job-level language)

**Step-level outcomes** are defined by exact set membership or exact counts, with no threshold:
- Step is OPTIMAL / SUBOPTIMAL / NON-DIAGNOSTIC (crush-forced) / UNREACHABLE (V = ∞) / K-MISMATCH / K-UNKNOWN / K-BLANK-START / pattern P-OPT / P-SEL / P-HEAD / P-BOTH / P-K3 / P-KUNK / P-CRUSH, as defined in §3.4–§3.5 and §4.1–§4.3. These are step-level labels, not job diagnoses.

**Job-level aggregation form (mandatory reporting format, even if no job-level claim is made):**
For each job, for each region (see below), report:
- **n_relevant** = number of steps in the region, excluding crush-forced steps from Dec/K denominators (crush-forced steps are reported in a separate crush denominator).
- **n_optimal, n_suboptimal, n_P-SEL, n_P-HEAD, n_P-BOTH, n_P-K3, n_P-KUNK** = counts of steps in the region with each label, with the denominator stated (n_relevant, or n_relevant_noncrush where applicable).
- **Proportions** = count / n_relevant (or count / n_relevant_noncrush, stated explicitly). Proportions are reported descriptively, without a threshold, unless a threshold has been set by the owner before collection (see below).
- **Episode spread** = number of episodes (out of 20) in which the pattern occurs at least once, and the set of start_phases in which it occurs. This is reported descriptively; it does not by itself constitute "systematic" until operationalised.

**Regions (job-level claims are per-region, not global, unless stated):**
- **Region E/D:** steps with position_before ∈ {E, D} (entry/exit cells). This is the primary region for crossing decisions.
- **Region W:** steps with position_before ∈ W (wall-adjacent, any row). This is the region for "reached the wall" analysis.
- **Region START:** steps with position_before in the start-side set (x < wx), excluding E/D/W as applicable for the sub-report (state the exclusion in the report).
- **Region GOAL-SIDE:** steps with position_before in the goal-side set (x > wx). In a failed held-out job this region should be empty or near-empty; if it is non-empty, the job crossed but failed to reach the goal, which is a different diagnostic situation from never crossing, and must be reported as such.
- A job-level claim that does not state its region is **incomplete** and must not be accepted as a job diagnosis.

**Job-level outcome rules (revised, threshold-aware):**
- **Job-level SUPPORTED (for Dec1, K2, K3, or a combined Dec/K claim) requires ALL of:**
  (a) n_relevant > 0 for the stated region;
  (b) the proportion of steps with the claimed pattern (e.g. P-SEL for Dec1) meets a **threshold set by the owner before collection** (for example, "≥ X% of relevant non-crush steps in Region E/D" — X is **not set by this revision** and must not be invented retrospectively);
  (c) the pattern occurs in at least a stated number of episodes / start_phases, also set by the owner before collection (the original "systematic" rule, now requiring operationalisation);
  (d) alternative patterns on the same steps are excluded by the step-pattern table (§3.5) — for Dec1, P-HEAD and P-BOTH must not account for the same steps; for K2, P-SEL must not account for them; for K3, K-mismatch precedence (§3.4) must have been applied.
  **Until (b) and (c) are set, job-level SUPPORTED for Dec/K/K3 cannot be assigned, and the job-level outcome is INCONCLUSIVE** (even if step-level patterns are clear). This is intentional: it prevents a single example or an unoperationalised "systematic" claim from becoming a job diagnosis.
- **Job-level NOT_SUPPORTED (exact cases, no threshold required):**
  - **Dec/K on Region E/D as sole cause:** if n_relevant (E/D, non-crush) > 0 **and** every such step is OPTIMAL (taken_action ∈ R(s)), then Dec/K cannot be the sole cause *for the E/D region* (the failure must be elsewhere: other regions, cap-fatal wandering, or execution). This does **not** by itself give a job-level NOT_SUPPORTED for Dec/K overall, unless all regions are also optimal (see consistency check below).
  - **K3 on a step/region:** if, on the stated region, every timing-critical step has K_rec = 1 with phase/remaining matching the true schedule, then K3 is NOT_SUPPORTED for that region (schedule knowledge was correct there).
  - **Ex1 as sole cause:** if crushes_total = 0 for the job, then Ex1-as-sole-cause is NOT_SUPPORTED for that job. **This does not exclude Ex2–Ex5, and therefore does not exclude execution as a whole** (see C10).
  - **Consistency check (must be applied, not optional):** if *every* non-crush step in *every* region of a failed episode is OPTIMAL, then either the reference computation or the trajectory recording is wrong, because optimal play from a recoverable start state must reach the goal within V(start) steps (see §3.2, cap-aware recoverability). In that case the episode's diagnostic outcome is **UNKNOWN** (recording/reference error suspected), not a policy diagnosis, and the discrepancy must be reported as a finding, not smoothed over.
- **Job-level INCONCLUSIVE:** any job-level claim where (b) or (c) above is unset, where n_relevant = 0 for the stated region, where step patterns are mixed (P-SEL, P-HEAD, and P-BOTH all present without a stated aggregation priority), or where the region is not stated.
- **Job-level UNKNOWN:** the job does not exist (L-SVA W20 seed 2), or the trajectory's clock alignment, geometry, or reference version is not stated, or the collection identifier / source-job link (§5, R-LINK) is missing.

### 4.5 Earliest failure — deviation vs inevitability (supersedes original §3.5 and §3.1E/§3.2E/§3.3E/§3.4E earliest-point language)

For each failed episode (reached = False, 200 steps, cap), report **both** of the following, defined exactly, and do not conflate them:
- **Earliest deviation:** the first non-crush-forced step s in the episode where taken_action ∉ R(s) (SUBOPTIMAL). If no such step exists, the episode's diagnostic is UNKNOWN by the consistency check in §4.4 (optimal play must have reached the goal). Earliest deviation is a *description* of where the trajectory first left the optimal set; it is **not** by itself a causal diagnosis, because a recoverable deviation (see below) does not make failure inevitable.
- **Earliest inevitability (cap-fatal step):** the first non-crush-forced step s in the episode where taken_action leads to a next state s' with V(s') > steps remaining after step s (200 − (s + 1)). After such a step, even optimal play cannot reach the goal before the cap. If the cap-fatal step is crush-forced, it is **not** counted as the inevitability step for decision/knowledge purposes; instead, trace back to the most recent step that moved the agent into D (entry step) or stayed in D while open (the step that placed the agent in D at a phase that would become closed), and report *that* step as the **preceding placement step** for the crush. The crush itself is a consequence, not the first failure.
- **Relationship:** earliest deviation ≤ earliest inevitability (in step order), because a deviation must occur before or at the step where recoverability is lost (optimal steps preserve recoverability, as shown in §3.2: V decreases by 1 and remaining decreases by 1, so V(s') ≤ remaining is preserved by optimal steps). If a diagnostic reports only the deviation and calls it "the cause", it overclaims: many deviations are recoverable, and the episode could still have succeeded after them. If a diagnostic reports only the inevitability step and calls it "the cause", it may miss the earlier pattern (for example, repeated suboptimal wandering that cumulatively wasted the cap, with the inevitability step being merely the last wasteful step). Both must be reported, with their step indices, positions, phases, actions, and reference sets, so that the owner can see whether the failure was a single critical error or cumulative waste.
- **For episodes that reach the goal:** earliest deviation and earliest inevitability are not defined (the episode succeeded; suboptimal steps in a successful episode are recoverable deviations, not failures, and must not be counted as decision errors for that episode's outcome).

## 8. Bounded conclusion — is the revised specification now internally consistent enough for owner review?

**Answer: Yes, for owner review — with the remaining limits stated below, which are limits of authorisation and measurement, not hidden inconsistencies.**

**What is now internally consistent (and was not, before):**
- Coverage and cause are no longer conflated (§2.1, C01/C02). A never-visited door is a coverage fact; a causal discovery claim requires a separate, stated mechanism and criterion, which greedy eval does not provide.
- The suitable-action reference is now a computed, model-independent set (§3.2, C03), not an example. It handles waiting, blocked equivalence, crossing windows (including the last-open-tick fatal case), multiple optima, and crush-forced states, by construction from the world's transition rules. It does not use the model's Q, choices, or failed trajectory as proof of suitability.
- The clock is now unambiguous (§4.1–§4.3, C05/C06). Every revised field carries t_pre/t_post, door_open_pre is governing, door_open_post is labelled post-transition only, crush is pre-movement on position_before, blocked is the world's own blocked log (not position equality), and stay/edge-clip are separate types. A one-tick misalignment is defined as INVALID for timing classification, not as evidence for a policy failure.
- Step-level and job-level outcomes are now separated (§4.4, C09). Step outcomes use exact set membership; job outcomes require a stated denominator, a proportion, and an owner-set threshold, plus episode spread. Until the threshold is set, job-level SUPPORTED for Dec/K/K3 is unavailable by design — that is a consistency feature, not a gap in the revision, because it prevents retrospective threshold invention.
- Scope matches data (§6, C07/C08). D1 and K1 are explicitly excluded from the first collection; Dec1 requires full Q or is excluded; Shared Dec/K mechanism separation is explicitly INCONCLUSIVE. The revision no longer implies a complete four-category discrimination from a held-out-only collection.
- Provenance is tightened (§5, R-LINK, C13) without changing any existing record: every future diagnostic record must link to its source job identifier *and* carry a distinct collection identifier, and the P-VAL gate remains a proposal, not an executed procedure.

**Remaining limits — stated explicitly, so that "consistent enough for review" is not misread as "ready for collection" or "diagnosis complete":**
1. **Job-level thresholds are still unset** (decision 3). The revision defines the *form* of the aggregation rule, but the numeric cut-offs (proportion, episode spread, loop definition, rarely-visited criterion, K1 distance) require owner decisions before collection. Until they are set, the strongest job-level statements available are exact exclusions (exact-zero crush for Ex1-as-sole-cause, exact-all-optimal on a region, exact-zero coverage as a fact) and descriptive step patterns. That is the correct state for a specification awaiting approval, but it means the revision alone does not authorise a job-level SUPPORTED claim.
2. **The reference DP has not been computed or verified in this revision.** §3.2 defines V and R(s) exactly, and states the finiteness expectation for the pilot worlds, but no V table was computed, because computation would be a (small) execution step and this work order authorises review/correction only. Before any collection that relies on R(s), the DP must be computed, its Bellman equation checked to exact integer equality, and its V table versioned (R-CFG). If the computation finds V = ∞ for any pilot state, that state must be marked UNREACHABLE, not treated as a decision error.
3. **D1 and K1 remain unmeasured by design.** The first collection cannot assess them, and this revision does not define their measurements beyond stating what additional evidence they require (training trajectories + expected-visitation reference for D1; trained-world trajectories + agreed distance for K1). A complete four-category diagnosis would require those additional steps, each with its own authorisation.
4. **Shared Dec/K mechanism separation remains INCONCLUSIVE by design.** No Q-based diagnostic observation, however complete, can separate selector from head mechanisms in a shared network without an intervention. If the owner requires that separation for Shared, a new experiment (forced-selector counterfactual) would be needed, which this revision does not authorise or design in full.
5. **Existing-evidence verdict is unchanged and remains INCONCLUSIVE (UNKNOWN for the missing job).** This revision corrects *how a future diagnostic would classify*; it does not create new pilot evidence, change any existing count, or upgrade any existing INCONCLUSIVE to SUPPORTED. Any reading of this revision as "the cause is now known" would be incorrect.

**Completion condition for this work order:** This revised specification (REVISION-01) is submitted for owner review and the work stops here. It is **not** authorisation for its proposed collection. Any collection requires a separate owner decision specifying its identifier, scope, source, and pooling rule (decision 4 in §7), plus the definitions/thresholds in decisions 1–3 that the collection will rely on.
