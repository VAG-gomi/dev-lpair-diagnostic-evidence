## 1. Modification A — KX2a versus availability-state assignment: replacement wording

### 1.1 The defect, stated exactly

REVISION-10 §2.2 requires KX2a to be evaluated before assigning a K_rec = 0 availability-state outcome ("availability classification except where KX2a fires; True + K_rec = 0 → INVALID-K with no availability-state outcome, gate-before-availability precedence" — REV-09 §2.2 as retained and qualified by REV-10 §2.7). REVISION-10 §4.1 E3, however, lists subsequent routing "in retained order: OPT routing, availability-state assignment, defect precedence D1–D4 for overlapping defects, §3 comparison, pattern classification." Read literally as an order, that list places availability-state assignment **before** defect precedence — so a True + K_rec = 0 step could be read as receiving an availability-state outcome before KX2a (a D3 defect) is evaluated, contradicting §2.2. The two descriptions therefore do not consistently establish which outcome wins. This erratum resolves the contradiction by correcting the E3 order, not by reordering defects or redesigning the tree.

### 1.2 Replacement wording (governing; supersedes the REV-10 passages listed in §4)

**Replacement E3 (to be read in place of REV-10 §4.1, E3's routing list, for every step that reaches E3):**

> **E3 — Subsequent routing (latest).** If T0-C passes (phase present and consistent), subsequent routing applies in the following order, and no later item in the order may override an earlier item's winning outcome for the same step:
>
> 1. **OPT routing** (retained position; unchanged by this erratum — see §1.3, note (ii)).
> 2. **Defect precedence D1–D4** for overlapping, determinable defects (retained order: D1 FIELD-MISSING > D2 EST-STATE > D3 INVALID-K > D4 INVALID-FEAT-RECORD). **KX2a is evaluated at this stage, before any availability-state assignment:** for a K_rec = 0 step, KX2a (True + K_rec = 0) is a D3 defect evaluated here, not after availability assignment.
> 3. **Availability-state assignment** (K_rec = 0 steps only), permitted **only if** (a) KX2a was evaluated and did **not** fire, **and** (b) no defect outcome won under D1–D4 at item 2. If either condition fails, no availability-state outcome is assigned.
> 4. **§3 comparison** (K_rec = 1 steps only, subject to §3 entry conditions and to §2 of this erratum for exception eligibility).
> 5. **Pattern classification** (for steps that receive a §3-derived step label, per REV-09 §4.1 precedence, retained).
>
> **KX2a-winning rule (governing).** When KX2a determines the winning outcome, assign **INVALID-K and no availability-state outcome**. The availability fields for such a step may be recorded descriptively in the step record (for audit: which availability state *would* have applied had KX2a not fired), but a descriptive note is **never** a winning classification, never an I0 summand, never an F/Q row entry, and never a P2 denominator classification on availability grounds. **No step can contribute to both INVALID-K and an availability-state outcome as its winning classification** (I0 single counting, REV-07 §4, retained): its one I0 summand is to INVALID-K, and its availability-state count is zero.

**Replacement §2.2 confirmation sentence (to be read alongside REV-10 §2.2, Gate FAIL, and REV-10 §2.7, K-flag route; it confirms, rather than changes, their substance):**

> KX2a-before-availability is implemented by the E3 order above (defects at E3 item 2, availability at E3 item 3). REV-10 §2.2's "gate-before-availability precedence" and REV-10 §2.7's "availability classification except where KX2a fires" are therefore not two separate orderings to be reconciled by the reader: they are the same rule, stated once in §2.2/§2.7 (substance) and once in corrected E3 (tree position). Any reading of REV-10 §4.1's original E3 list in which availability-state assignment precedes defect precedence is superseded by the replacement E3 above.

### 1.3 Notes that bound Modification A (governing; these notes are part of the correction, not commentary)

- (i) **D1–D4 order unchanged.** This erratum does not reorder D1, D2, D3, or D4 relative to each other, does not change any defect's firing condition (KX2a, KX2b/c/d-span/d-open/e/f, EST-PROV clauses (a)/(b) — all retained), and does not change any defect's waste bucket (defect outcomes remain unassigned, REV-05 §6 / REV-07 §4, retained). The only order changed is availability-state assignment relative to defect precedence within E3 (availability moves after defects, for K_rec = 0 steps).
- (ii) **OPT position unchanged.** OPT routing retains its position at E3 item 1, as in REV-10 §4.1's retained order. This erratum does **not** adjudicate any OPT-versus-defect ordering question beyond the KX2a-versus-availability question it was authorised to resolve: for a step that is both OPT-routed and defect-bearing, the retained tree/partition order governs as before, and any ambiguity there (if one is later demonstrated with a concrete step pattern) is a separate, non-blocking item for a future, separately authorised correction — it is not introduced by this erratum, and it does not affect the KX2a rule, because KX2a applies only to K_rec = 0 steps and availability assignment applies only to K_rec = 0 steps, so the KX2a-versus-availability ordering is fully determined by items 2–3 above regardless of OPT's position.
- (iii) **§2.7 and row G4 reconciled (governing).** REV-10 §2.7's route (flag recorded 0 → availability-state routing, subject to KX2a exception) is now read as: flag recorded 0 → E3 item 2 (KX2a and other defects) → if no defect wins, E3 item 3 (availability-state outcome: KBLANK / KNEVER / KUNK / phase-only sub-states / K-STATUS-UNKNOWN as applicable). REV-10 §7 row G4 (gate FAILS, KX2a: True + K = 0 → INVALID-K, I0 1 summand to INVALID-K, 0 to any availability-state count) is **confirmed correct as written** and is now expressly grounded in corrected E3 items 2–3 (previously it rested on §2.2 alone against §4.1's conflicting list; the conflict is removed). No change to G4's columns is needed; G4's I0 column ("0 to any availability-state count") is the direct consequence of §1.2's KX2a-winning rule.
- (iv) **Descriptive availability reporting, bounded.** "Descriptive availability reporting only" (REV-09 §2.2 / REV-10 §2.7, retained) means: the step record may state the availability state that would have applied (e.g., "would-be KBLANK, not counted"), for audit traceability. It does **not** mean the step appears in any availability-state count, total, denominator, or cross-tabulation row. A report that sums a descriptive availability note into an availability-state total violates single counting and must be corrected to zero for that step's availability-state count.

## 2. Modification B — no component outcomes after an earlier tree exit: replacement wording

### 2.1 The defect, stated exactly

REVISION-10 §7 row G2 permits the other component (recorded remaining, present) to receive a §3 matrix outcome even though the step exits at E2 with FIELD-MISSING-PATTERN because its recorded phase is missing. Under the retained matrix-entry definition (REV-08 §2, retained: a P- attribute, and by the same definition a §3 component outcome, exists only for a component to which the §3 matrix assigns an outcome, which requires the step to reach §3), a step that exits before §3 does not receive component outcomes or P- attributes. G2's "other component per matrix" clause therefore contradicts the matrix-entry definition, and the same contradiction affects REV-10 §8 case W10-2's derivation step (2) ("No §3 component outcome for phase" — implying, by omission, that the remaining component's outcome stands) and any reading of REV-10 §§2.3–2.5 in which an exception flag alone could create a §3 outcome for a step that never reaches §3. This erratum corrects G2, W10-2, and the exception-eligibility rule; it does **not** change any component-comparison rule for steps that legitimately reach §3.

### 2.2 Replacement wording (governing; supersedes the REV-10 passages listed in §4)

**Replacement §3-entry rule (to be read as a precondition on REV-10 §2.3 exception definition, REV-10 §2.4 pending definition, REV-10 §2.5 claim scope, and REV-10 §1/§10 P- domain statements):**

> **§3 reach is a precondition for every §3 component outcome and every P- attribute.** A step receives a §3 component outcome (for either component: phase or remaining) **only if** the governing tree permits the step to reach §3 — that is, no earlier tree exit has won for the step (E0 type exclusion, E1 T0-P failure, E2 FIELD-MISSING-PATTERN or T0-C INVALID-RECORD, or defect routing that pre-empts §3, per REV-10 §4 exit order and REV-10 §2.2 Gate FAIL), **and** the step is a K_rec = 1 candidate for §3 (REV-08 §2 / REV-10 §2.7, retained). If the step exits before §3 for any reason, it receives **no §3 component outcome for either component** and **no P- attribute for either component** (both components shown as "—", the REV-08 §2 absence marker, which is not a value and not a sixth P- value), regardless of whether one component's comparison inputs happen to be present and evaluable. Present values for the non-exited component may be recorded descriptively in the step record ("comparison not performed; step exited at <exit>, <reason>"), but a descriptive note is never a component outcome, never a P- attribute, never a step-level fall-through input, and never an I0/F/Q summand on §3 grounds.

**Replacement exception-eligibility rule (to be read as an additional condition on REV-10 §2.3, GATE-UNEVALUABLE, and on REV-09 §3.2, E-TUPLE, as retained by REV-10):**

> **GATE-UNEVALUABLE and E-TUPLE permit exception-flagged classification only when the governing tree otherwise permits the step to reach §3.** Each exception therefore has **three** eligibility conditions, all required (replacing any two-condition reading of REV-10 §2.3): (i) the tree permits the step to reach §3 (no earlier exit won; K_rec = 1; T0-C passed; no defect routing pre-empted §3); (ii) classification inputs for the applicable §3 comparison are present and sufficient; (iii) the named check (gate check for GATE-UNEVALUABLE, EST-PROV clause (a) for E-TUPLE) is unevaluable due to omitted provenance/availability inputs. If condition (i) fails, **neither exception applies**, even if conditions (ii) and (iii) hold for one component: the step's outcome is its earlier exit (e.g., FIELD-MISSING-PATTERN at E2), no exception flag is applied (an exception flag presupposes a §3 outcome to flag; applying it to a non-§3 step would imply a §3 outcome exists), and any unevaluated check is recorded descriptively only ("check not evaluated; step exited at <exit>, so exception does not apply"), never as GATE-UNEVALUABLE or E-TUPLE. Conditions (ii) and (iii) alone never override an earlier winning exit.

**Replacement pending-note for pre-§3 exits (to be read alongside REV-10 §2.4, UNEVALUABLE-PENDING):**

> Where a step exits before §3 (E0/E1/E2 or defect routing), the step's gate-check state is **NOT REACHED** (not UNEVALUABLE-PENDING and not GATE-UNEVALUABLE), because gate evaluation is reached only at the §3/gate stage, which the step never entered. A DATA-PENDING flag may still be carried for a §3 attribution **only** in the following, narrow sense: it records the **absence** of §3 outcomes for the step (attribution: "§3 component outcomes", cause: the missing field and/or the exit that pre-empted §3, tree outcome: the earlier exit's outcome) — it does **not** record a §3 outcome awaiting assignment within §3, and it does **not** imply that the step's §3 comparison is pending determination. Where no §3 attribution is sought at all (the step's governing analysis does not require a §3 outcome for any purpose), no DATA-PENDING flag is needed; a descriptive note suffices (cf. REV-10 §7 rows A1–A2 notes, retained). The flag, where carried, is an attribute (zero additional I0 summands, REV-07 §4, retained) and supports no frequency, waste, pattern, or accounting claim for any §3 attribution (§2.4 of REV-10, retained, now with the absence-meaning made explicit for pre-§3 exits).

### 2.3 Consequences that follow from Modification B (governing; stated so no downstream rule can be read inconsistently)

- **P- domain (governing).** The P- attribute domain (REV-08 §2, retained by REV-10) is now stated with its §3-reach condition explicit: a P- attribute exists **only** for a component to which the §3 matrix assigns an outcome, which requires the step to reach §3. E2-exit steps (FIELD-MISSING-PATTERN, T0-C INVALID-RECORD), E0/E1-exit steps, defect-routed steps (INVALID-K / INVALID-FEAT-RECORD / INVALID-EST-STATE as winning outcome), and K_rec = 0 steps (availability outcomes) all show "—" for both components. No P- value (including P-UNKNOWN) may be assigned to a non-§3 step on the grounds that its consistency is "unknown": unknown consistency for a non-§3 step is recorded as absence ("—"), not as P-UNKNOWN (P-UNKNOWN is a value for a **matrix** component whose partial comparison is incompletable — REV-07 §3 / REV-08 §2, retained — and therefore presupposes §3 reach).
- **Step-level fall-through (governing).** Step-level fall-through (REV-08 §3, retained: all-or-nothing over the complete component combination) requires a complete component combination **from §3**. An E2-exit step has no component combination (both components absent), so it **cannot** fall through, cannot receive a pattern outcome via fall-through, and cannot contribute to any fall-through count or frequency. Its descriptive totals are FIELD-MISSING-PATTERN totals only.
- **I0 single counting (governing).** An E2-exit step contributes exactly one I0 summand: to FIELD-MISSING-PATTERN (or to its earlier-exit outcome where E0/E1 applies). It contributes zero summands to any §3 component-outcome count, zero to any P- attribute count, zero to any pattern count, and zero to any assigned-pattern waste sum. The previous G2 reading (other component per matrix) would have contributed a second, §3-grounded count for the same step alongside its FIELD-MISSING-PATTERN summand; that double-grounded counting is the error corrected here, and any report retaining it violates single counting (REV-07 §4, retained).
- **Matrix comparison rules unchanged (governing).** For steps that **do** reach §3 (no earlier exit, K_rec = 1, T0-C passed), every component-comparison rule is unchanged: est_full × completability × recorded relations → exactly one outcome per component (REV-05 §3, retained), governing comparison per estimate/completability (REV-08 §3, retained), precedence INCONSISTENT-C > UNRESOLVED-C > fall-through-eligible (REV-09 §4.1, retained), and exception rules GATE-UNEVALUABLE / E-TUPLE with the §3-reach condition added by §2.2 of this erratum. No component's comparison (KF1/KF2, partial-match, MATCH-TRUE, INCONSISTENT-C, UNRESOLVED-C) changes its definition or its firing condition for §3-reaching steps.
- **Other rows/cases read with the §3-reach condition (governing).** REV-10 §7 rows G1 and G3 and §8 case W10-1 are **retained as written, with one explicit assumption added by this erratum**: each applies only where the tree permits the step to reach §3 (T0-C passed, no earlier exit, no defect routing pre-empting §3, K_rec = 1). That assumption was implicit in REV-10 (their inputs state K flag = 1, values present, no defect, and no earlier exit is mentioned); this erratum makes it explicit so that G1/W10-1 cannot be cited for a step that exits at E2. If a future report cites G1/W10-1 for a step, it must state the §3-reach condition (or show T0-C passed and no earlier exit) alongside the citation, or the citation is incomplete. REV-10 §7 rows G5/G6 (K-flag route, availability) already assign no §3 component outcomes and are unaffected by Modification B (G5: FIELD-MISSING-PATTERN, no §3 outcomes — consistent; G6: availability outcome, no §3 outcomes — consistent).

## 3. Clarification C — complete exit order for a missing K flag (cross-reference clarification, not a redesign)

### 3.1 Governing order (to be read alongside REV-10 §2.7 and REV-10 §4.1)

The K-flag routing in REV-10 §2.7 is explicitly subordinate to earlier applicable exits in the full tree order. For a step with a missing K flag (R-K-FLAG NOT-RECORDED), apply the following order, and stop at the first exit that wins (single counting, REV-07 §4, retained):

1. **E0 — Type exclusion wins first.** If the step is CRUSH-ND, TERMINAL, or UNREACH, the step outcome is the exclusion outcome. Missing K flag (if also present) is recorded descriptively only ("K flag also missing; routing not reached") — it does **not** determine the winning outcome, does **not** contribute a FIELD-MISSING-PATTERN summand, and does **not** create a DATA-PENDING flag for K-status routing (no K-status attribution is sought, because the tree exited at E0; cf. REV-10 §7 rows A5/A6 descriptive-note pattern, retained).
2. **E1 — T0-P failure wins before later K-flag routing.** If any T0 identity/ordering field for the step is missing, the step outcome is INVALID-RECORD (REV-10 §4.1 E1, retained). Missing K flag (if also present) is recorded descriptively only, on the same terms as item 1 (no FIELD-MISSING-PATTERN summand, no K-status DATA-PENDING flag, no K-STATUS-UNKNOWN consideration — K-STATUS-UNKNOWN requires a recorded 0 flag, which is absent, and in any case routing was not reached).
3. **E2 — The applicable T0-C outcome wins before E3 routing.** If E0/E1 do not apply (step not type-excluded, T0 fields present), the tree reaches T0-C:
   - If recorded phase is missing → FIELD-MISSING-PATTERN wins (REV-10 §4.1 E2, retained). The missing K flag is recorded descriptively only. It does not participate in E2 routing, become a co-reason for the E2 outcome, create a K-status attribution, or produce an additional summand. The E2 outcome is determined by the missing-phase route; the K-flag absence may be documented separately as descriptive metadata.
   - If recorded phase is present but inconsistent → INVALID-RECORD wins (T0-C outcome, retained). Missing K flag is recorded descriptively only, on the same terms.
   - If recorded phase is present and consistent → T0-C passes, and only then does the tree proceed to E3.
4. **E3 — Only when the tree reaches the relevant later routing stage may a missing K flag determine the winning FIELD-MISSING-PATTERN outcome.** At E3 (T0-C passed), routing proceeds per corrected E3 order (§1.2 of this erratum: OPT routing, then defect precedence D1–D4, then availability-state assignment, then §3 comparison, then pattern classification):
   - **Missing K flag (NOT-RECORDED) at E3:** the step cannot be routed as K_rec = 1 or K_rec = 0 (no recorded flag value to route on, REV-10 §2.7, retained). Tree outcome is **FIELD-MISSING-PATTERN** (missing-field bridge, D1, retained), with flag `DATA-PENDING-K-status` (attribution "K status", cause "R-K-FLAG NOT-RECORDED", tree outcome FIELD-MISSING-PATTERN — REV-10 §2.7, retained). This is the **only** position in the tree order at which a missing K flag, by itself, determines the winning outcome. Other missing-field conditions present at E3 alongside the missing flag (e.g., another feature field missing) are **co-reasons** for the same single FIELD-MISSING-PATTERN outcome (recorded with all missing field names in the reason, one summand, not one summand per field). Later defects (D2–D4) determinable on present fields at E3 are recorded as secondary attributes (zero additional summands, per REV-10 §4.2 D1-precedence-at-E2 principle, applied here at E3 for the D1 missing-field outcome); later defects undeterminable because of missing fields are recorded as DATA-PENDING flags for their own attributions (zero additional summands), never as defect outcomes and never as assumed-passed checks.
   - **Recorded K flag at E3:** flag = 1 → §3 candidate (subject to gates, defects, and §2.2 exception eligibility of this erratum); flag = 0 → E3 items 2–3 (KX2a and other defects first, then availability-state outcome only if no defect won — §1.2 of this erratum). In particular, a recorded 0 flag with unknown status provenance gives K-STATUS-UNKNOWN (availability-state outcome, REV-10 §2.7, retained) **only** at this E3 availability stage (KX2a evaluated and not fired, no defect won); it never applies to a NOT-RECORDED flag, and it never applies to a step that exited at E0/E1/E2.

### 3.2 What Clarification C does not change (governing)

- The distinction between a K flag that is NOT-RECORDED and a recorded K = 0 flag with unknown provenance is **unchanged** (REV-10 §2.7, retained): NOT-RECORDED → FIELD-MISSING-PATTERN (at E3, per §3.1 item 4; descriptively only at E0/E1/E2); recorded 0 + provenance unknown → K-STATUS-UNKNOWN (at E3 availability stage only, per §3.1 item 4). Neither outcome applies at an earlier exit, and the two are never equated and never double-counted.
- Single counting is **unchanged** (REV-07 §4, retained): one step, one winning I0 summand, regardless of how many missing fields or secondary conditions it carries. Other missing-field conditions on a step whose winning outcome is determined at E0/E1/E2 are recorded **only** as permitted secondary attributes (where determinable on present fields and where the attribute table provides for them, REV-07 §4, retained) or as descriptive notes (where the governing analysis does not seek an attribution for them), or as DATA-PENDING flags **only** where an attribution is genuinely sought but undetermined on missing data (REV-10 §5.2, retained, as narrowed by §2.2 of this erratum for pre-§3 exits: where the tree exited before the attribution's stage, the flag records absence, not pending determination, or a descriptive note suffices where no attribution is sought). No missing-field condition on an E0/E1/E2-exited step may be upgraded to a second winning outcome, a second I0 summand, or a P- attribute.
